# StudioIndex — Report RPP via email

WordPress plugin that receives the PDF generated by the StudioIndex **RPP calculator** (revenue per person), saves the contact as a lead, emails the report to the user and gives the site administrator a full list of requests, with reCAPTCHA and anti-spam protections.

- **Version:** 3.1.0
- **License:** GPL-2.0-or-later
- **Admin interface language:** Italian

## What it does

1. The calculator on the site posts the form data and the generated PDF (base64) to a REST endpoint.
2. The plugin validates everything, **recalculates RPP and cluster server-side** (values sent by the browser are ignored), and stores the PDF outside public URLs.
3. The user receives an email with the report attached, a secure download link and a **"Prenota la call"** button.
4. If the user presses the button, the studio gets a "to call back within 24 hours" email and the lead appears in a dedicated list.

## Admin menu

The plugin adds a **Lead RPP** menu:

| Page | Purpose |
|---|---|
| **Richieste** | All leads, with filters (date, cluster, region), search, sorting, PDF view, delete and CSV export |
| **Richieste di call** | Only people who asked to be called back, with a "contacted / to contact" status |
| **Impostazioni** | reCAPTCHA keys, notification recipients, optional internal copy of each report |
| **Email SMTP** | Outgoing mail server, changeable from the panel without touching the code, with a test send |

### Email SMTP

Set server, port, encryption (SSL/TLS, STARTTLS or none), user, password, sender email and name from **Lead RPP → Email SMTP**.

- Applies **only to this plugin's emails**; other WordPress emails are not touched.
- When active, the sender is the authenticated mailbox, so the server accepts the message.
- The password is stored **encrypted** (libsodium, key derived from the WordPress salts) and is never shown again. Leave the field empty on later saves to keep it. If the WordPress salts change, the password must be re-entered.
- **Invia email di prova** sends a test email with the saved settings and shows the server dialogue; credentials are masked in the log.
- A 15-second connection timeout prevents a blocked port from hanging the visitor's form.
- An optional checkbox disables certificate verification, for hosts whose certificate is issued for a different name.

SPF and DKIM on the sender's domain are still needed to keep attachments out of spam.

## Installation

1. Copy `studioindex-report.php` to `wp-content/plugins/studioindex-report/studioindex-report.php`.
2. Activate **StudioIndex — Report RPP via email** in the WordPress plugin list.
3. Open **Lead RPP → Impostazioni** (reCAPTCHA, recipients) and **Lead RPP → Email SMTP**.

## REST API

Namespace: `studioindex/v1`

| Method | Route | Description |
|---|---|---|
| `POST` | `/report` | Submit a request (fields below) |
| `GET` | `/config` | Public data only: reCAPTCHA mode and site key, so the front-end block can adapt |
| `GET` | `/call?id=&t=` | "Prenota la call" button in the email; `t` is an HMAC signature |
| `GET` | `/download?id=&t=` | The user's own report download; `t` is an HMAC signature |

`/report` fields: `nome`, `email`, `telefono`, `regione`, `attivita`, `fatturato`, `addetti`, `consenso`, `pdf` (base64), `recaptcha` (when enabled), `website` (honeypot, must stay empty).

## Protections

- reCAPTCHA v2 or v3 (optional, enabled from the settings)
- Honeypot field, Origin/Referer check, mandatory user agent
- Rate limits: 10 requests per IP per hour, 20 per IP per day, 5 per email address per day
- Server-side recalculation of RPP and cluster; closed lists for region and activity
- Limits on lengths and numeric ranges; PDF size capped at 2 MB
- `%PDF` signature and `%%EOF` marker checked before saving
- PDFs are not reachable by public URL: admin access goes through `admin-post.php` with nonce and `manage_options`, with a `realpath` check against path traversal
- Users' own downloads and call links are protected by HMAC-signed tokens
- No hand-written SQL, only `WP_Query`; nonce and capability on every backend action; escaped output

## Data

- Leads are stored in the custom post type `sx_lead`.
- PDFs are stored in `wp-content/uploads/studioindex-reports/`.
- Settings are stored in the options `sx_settings` (reCAPTCHA, recipients) and `sx_smtp` (mail server).

## Hooks

| Filter | Default |
|---|---|
| `studioindex_from_email` | SMTP sender if SMTP is active, otherwise `noreply@<site domain>` |
| `studioindex_from_name` | SMTP sender name if set, otherwise `StudioIndex` |
| `studioindex_notify_emails` | Notification recipient list, before sending |

## Requirements

The SMTP password encryption uses libsodium: the PHP extension, or the polyfill bundled with WordPress 5.2 and later. Without either, the password is stored unencrypted.
